# Blockchain Fundamentals

:::info Time estimate
**Reading:** 16 min · **Videos:** 32 min · **Exercise/review:** 10 min · **Total:** about 58 min
:::

## Learning objectives

By the end, you should be able to explain the core mechanism in plain language, identify its main risks, and apply it to a realistic decision.

## Lesson

### The core idea

A blockchain is a replicated, append-oriented ledger. Participants independently validate proposed changes under shared rules. Blocks group valid transactions; each block references earlier history, making silent rewriting increasingly difficult.

### How it works

Hash functions create fixed-length fingerprints. A tiny input change produces a different hash. Digital signatures let a private-key holder authorize a message while others verify it with the public key. Neither mechanism hides every detail; public chains are typically pseudonymous, not anonymous.

### Why it matters

Bitcoin uses an unspent transaction output model. Many smart-contract networks use account balances. Both answer the same core questions: is the spender authorized, are funds available, and does this state transition obey the protocol?

### Safety-first takeaway

A blockchain is valuable when multiple parties need a shared state without trusting one database operator. It is usually inefficient when a normal controlled database already fits the problem.

## Knowledge check

<details>
<summary>What should you understand before risking funds?</summary>

The transaction path, custody model, fees, failure modes, recovery procedure, and legal/tax recordkeeping—not merely a price prediction.

</details>

<details>
<summary>What is the safest response when you cannot explain a mechanism?</summary>

Pause. Research it with primary sources and, when appropriate, use a no-value simulation or small test rather than increasing exposure.

</details>
